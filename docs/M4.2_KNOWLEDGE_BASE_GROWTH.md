# Milestone 4.2: Continuous Knowledge Base Growth Mechanism

## 1. Overview & Objectives

The **Knowledge Base Growth Mechanism (M4.2)** establishes an automated, high-assurance pipeline for continuously enhancing the platform's Historical Defect Knowledge Base using newly resolved defects and verified fixes from the active platform.

By promoting resolved platform bugs into the vector knowledge store without disrupting existing historical records (Mozilla, Apache, Eclipse), the diagnosis platform becomes **self-improving**—accumulating empirical precedents that directly improve downstream accuracy for the Root Cause Agent, Duplicate Detection Agent, and Remediation Agent.

---

## 2. Architecture & Data Flow

```
   ┌─────────────────────────────────────────────────────────────┐
   │                    Resolved Platform Bug                    │
   │  - Title, Description, Component, Logs, Diagnosis Findings │
   └──────────────────────────────┬──────────────────────────────┘
                                  │
                                  ▼
   ┌─────────────────────────────────────────────────────────────┐
   │              Multi-Criteria Quality Gate (M4.2)             │
   │  1. Description Completeness (Title >=5, Desc >=15 chars)   │
   │  2. Architectural Component Identification                  │
   │  3. Error Diagnostics & Runtime Stack Trace (>15 chars)     │
   │  4. Root Cause Grounding & Causal Explanation               │
   │  5. Confirmed Resolution & Actionable Fix Patch (>=10 chars)│
   │  6. Indexing Idempotency & Duplicate Prevention             │
   └──────────────────────────────┬──────────────────────────────┘
                                  │ Passes Quality Gate (Score >= 0.65)
                                  ▼
   ┌─────────────────────────────────────────────────────────────┐
   │                   KBGrowthService Engine                    │
   │  - Assigns Unique Platform Defect ID: PLATFORM-<HEX>        │
   │  - Saves Structured Record to `historical_defects` (SQLite) │
   │  - Chunks Bug Data via `chunk_historical_bug()`             │
   │  - Computes 384-dimensional Embeddings (all-MiniLM-L6-v2)  │
   │  - Executes Non-Disruptive VectorStore Upsert (ChromaDB)    │
   │  - Updates Platform Bug: status="Resolved", indexed=True    │
   └──────────────────────────────┬──────────────────────────────┘
                                  │
                                  ▼
   ┌─────────────────────────────────────────────────────────────┐
   │               Downstream RAG Knowledge Store                │
   │  - Root Cause Agent retrieves platform resolution precedent │
   │  - Duplicate Detection matches future similar incidents     │
   │  - Remediation Agent proposes verified historical code patch│
   └─────────────────────────────────────────────────────────────┘
```

## 3. Minimum Information Requirements & Quality Gate

To prevent index pollution and ensure high retrieval precision, defects must satisfy strict validation rules before promotion:

| Criterion | Minimum Threshold | Purpose |
| :--- | :--- | :--- |
| **Defect Description** | Title $\ge 5$ chars, Description $\ge 15$ chars | Ensures sufficient lexical context for embeddings |
| **Target Component** | Specific architectural subsystem | Enables component-scoped filtering |
| **Error Logs & Trace** | Stack trace $> 15$ chars OR error logs $> 10$ chars | Provides runtime error signature for vector matching |
| **Root Cause** | Agent root cause hypothesis OR causal notes | Explains the underlying defect mechanism |
| **Confirmed Resolution** | Verified fix notes $\ge 10$ chars & optional code patch | Actionable remediation guidance for developers |
| **Idempotency** | `indexed_in_kb == False` | Blocks duplicate vector insertion and corruption |

## 4. API Endpoints (`backend/app/api/kb_growth.py`)

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `POST` | `/api/knowledge-base/growth/resolve/{bug_id}` | Submits resolution notes, code patch, and updates bug status to `Resolved` |
| `GET` | `/api/knowledge-base/growth/validate/{bug_id}` | Runs Quality Gate audit and returns itemized criteria, score, and eligibility |
| `POST` | `/api/knowledge-base/growth/promote/{bug_id}` | Validates Quality Gate, generates 384-d embeddings, upserts to ChromaDB, and indexes to relational DB |
| `GET` | `/api/knowledge-base/growth/candidates` | Returns defects eligible for promotion with quality gate statuses |
| `GET` | `/api/knowledge-base/growth/stats` | Returns real-time knowledge base growth metrics, source breakdown, and recent promotions |

## 6. Verification & Automated Test Coverage

The module is verified via `tests/test_kb_growth.py`:
- `test_kb_growth_stats_endpoint`: Validates growth metrics and source counts.
- `test_kb_growth_candidates_endpoint`: Validates candidate defect evaluation.
- `test_quality_gate_rejection_for_incomplete_bug`: Validates rejection of defects lacking stack traces or descriptions.
- `test_resolution_and_promotion_workflow`: Full end-to-end integration test verifying:
  1. Bug submission with logs and stack trace.
  2. Resolution notes and code patch submission.
  3. Quality gate validation pass.
  4. Vector embedding generation and ChromaDB upsert.
  5. Relational persistence in `HistoricalDefect` with `dataset_source="Platform"`.
  6. Idempotency enforcement preventing duplicate indexing.
  7. Downstream semantic vector retrieval confirming the new defect is returned for relevant queries.
