# Milestone 4.1: Defect Pattern Analytics Module

## 1. Overview & Objectives

The **Defect Pattern Analytics Module** identifies recurring patterns, failure density hotspots, common root causes, and semantic clusters across all submitted software bugs and historical defect repositories (Mozilla, Apache, Eclipse).

### Core Capabilities
1. **Multi-Dimensional Defect Categorization**: Evaluates defects across Severity, Priority, Affected Component, Exception Signature, Root Cause Theme, and Duplicate Status.
2. **Component Hotspot Identification**: Highlights subsystems experiencing recurring defect clusters to prioritize refactoring and architectural hardening.
3. **Failure Signature Mining**: Automatically extracts runtime exception types (`NullPointerException`, `TimeoutException`, `SQLException`, etc.) and traces frequent failure call frames (`file:line`).
4. **Root Cause & Remediation Themes**: Classifies defects into actionable causal themes and correlates them with proven historical fix code patterns.
5. **Semantic Bug Clustering**: Employs 384-dimensional vector embeddings (`all-MiniLM-L6-v2`) and cosine similarity thresholds to group semantically similar defects into coherent clusters.
6. **Temporal Trend Analysis**: Analyzes defect arrival velocity and frequency over time (Increasing, Decreasing, or Stable).
7. **Interactive Multi-Filter Scope**: Enables filtering by Component, Severity, Priority, Exception Type, and Data Source (Submitted vs Historical vs All).

## 3. Data Models & API Specifications

### Output Schemas (`backend/app/schemas/analytics.py`)

- `AnalyticsKPIs`: `total_defects_analyzed`, `recurring_pattern_rate`, `top_affected_component`, `critical_high_percentage`, `duplicate_defect_count`.
- `ComponentHotspot`: `component`, `defect_count`, `percentage_of_total`, `critical_count`, `high_count`, `recurrence_rate`, `top_exceptions`, `risk_level`.
- `ExceptionPattern`: `exception_type`, `occurrence_count`, `percentage`, `affected_components`, `sample_failure_points`.
- `RootCauseTheme`: `theme_id`, `theme_name`, `description`, `frequency`, `percentage`, `common_remediations` with code snippets.
- `SemanticCluster`: `cluster_id`, `cluster_theme`, `defect_count`, `average_similarity`, `representative_defect`, `members`.
- `TimeTrendAnalysis`: `interval`, `trend_direction` (Increasing/Decreasing/Stable), `velocity_percentage`, `timeline`.

### Endpoints (`backend/app/api/analytics.py`)

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/analytics/overview` | Full aggregated analytics dashboard payload |
| `GET` | `/api/analytics/components` | Ranked component hotspots and failure risk |
| `GET` | `/api/analytics/exceptions` | Recurring exception types and stack trace frames |
| `GET` | `/api/analytics/root-causes` | Recurring root causes and remediation code snippets |
| `GET` | `/api/analytics/clusters` | Semantic defect clusters with similarity scores |
| `GET` | `/api/analytics/trends` | Time-series volume and velocity progression |
| `GET` | `/api/analytics/filters` | Distinct filter options (components, severities, etc.) |

## 4. Verification & Automated Test Coverage

The module is verified using **Pytest** in `tests/test_analytics.py`:
- `test_analytics_overview_endpoint`: Validates the full aggregated JSON response.
- `test_component_hotspots_endpoint`: Validates risk level calculation and sorting.
- `test_exception_patterns_endpoint`: Validates regex extraction of runtime errors.
- `test_root_cause_themes_endpoint`: Validates mapping to remediation code templates.
- `test_semantic_clusters_endpoint`: Validates vector similarity clustering.
- `test_time_trends_endpoint`: Validates time-series direction and velocity.
- `test_analytics_filters_endpoint`: Validates filter discovery.
- `test_analytics_service_filtering`: Directly verifies SQL and in-memory filter execution.
