# Historical Bug Datasets Guide

This directory holds the raw, sample, and processed historical defect datasets used by the **Intelligent Bug Diagnosis Platform with Fix Recommendation Assistance**.

---

## 1. Directory Structure

```
data/
├── raw/
│   ├── mozilla/        <-- Place downloaded Kaggle Mozilla Bugzilla dataset files here
│   ├── apache/         <-- Place downloaded Kaggle Apache Jira dataset files here
│   └── eclipse/        <-- Place downloaded Kaggle Eclipse Bugzilla dataset files here
├── sample_data/        <-- Verified historical defects bundled for immediate local execution
│   ├── mozilla_sample.json
│   ├── apache_sample.json
│   └── eclipse_sample.json
├── processed/          <-- Cleaned, standardized, chunked records generated by scripts/process_datasets.py
└── README.md           <-- This instructions file
```

---

## 2. Dataset Sources & Kaggle Downloads

The platform is designed to ingest public bug datasets commonly sourced from Kaggle:
- **Mozilla Defect Dataset**: Sourced from Mozilla Bugzilla (contains browser rendering crashes, JavaScript engine exceptions, and network socket bugs).
- **Apache Defect Dataset**: Sourced from Apache Software Foundation Jira (e.g., Apache Spark, Lucene, Hadoop, Commons; contains concurrency deadlocks, null pointer exceptions, and I/O failures).
- **Eclipse Defect Dataset**: Sourced from Eclipse Bugzilla (e.g., Eclipse Platform, JDT compiler, Equinox; contains OSGi bundle errors, SWT UI thread violations, and compiler syntax exceptions).

### Download Links & Search Queries on Kaggle:
1. Search Kaggle for: `mozilla bug report dataset`, `apache jira issues dataset`, or `eclipse bug report dataset`.
2. Extract the downloaded CSV, TSV, or JSON files into their respective subdirectories:
   - `data/raw/mozilla/`
   - `data/raw/apache/`
   - `data/raw/eclipse/`

---

## 3. Why Raw Datasets Are Not Committed to Git

Raw bug datasets from Kaggle often span several hundred megabytes to gigabytes. Committing such large binaries violates Git best practices, bloats repository clone times, and risks merge conflicts. The `.gitignore` file is configured to exclude `data/raw/*` and `data/processed/*` while preserving the folder layout and bundled sample data in `data/sample_data/`.

---

## 4. How to Process the Datasets

To automatically detect column formats, clean records, generate chunks, compute embeddings, and load vectors into ChromaDB:

### Option A: Process Kaggle Datasets (When downloaded)
```powershell
python scripts/process_datasets.py
```

### Option B: Process Bundled Sample Datasets (Immediate offline test)
```powershell
python scripts/process_datasets.py --sample
```

The script will:
1. Inspect each directory for `.csv`, `.tsv`, or `.json` files.
2. Auto-map field names (e.g., `Issue key`, `bug_id`, `Summary`, `Description`, `Resolution`).
3. Sanitize empty descriptions and duplicate IDs.
4. Generate cohesive semantic chunks with metadata tags.
5. Compute 384-dimensional vector embeddings via `all-MiniLM-L6-v2`.
6. Persist vectors and metadata in the local ChromaDB database.
